### R1 — Onboarding（Q2 已裁決 2026-07-31：維持進階功能，不進主路徑）

**現況**：這個 app 沒有 onboarding，只有空狀態。`TilingLayout.tsx:482` 的
「Link your first project to get started」與 `Sidebar.tsx:698` 的「No projects linked yet.」
就是全部。Coordinator 是 `NewTaskDialog` 裡的一個 checkbox，Arena 在 `SidebarFooter`。

**建議：Coordinator 與 Arena 維持進階功能，不進 onboarding 主路徑。** 三個理由：

1. PRD 自己把 Arena 全部標為 **P2**，Coordinator 的 `FR-COORD-01`～`09` 幾乎都是 P0
   且大半在講失敗處理（MCP server 起不來、控制權切換失敗、token 越權）。
   把最難的失敗模式擺在新使用者面前，是最容易流失的地方。
2. 產品的核心價值（PRD §5.1）是「單一任務的 worktree 隔離」。第一次使用要成立的是這件事。
3. Coordinator 需要 MCP server + token wiring 才能啟動，那是唯一會因為環境問題整段失敗的路徑。

**做法：三階段漸進揭露，不做 wizard。**

| 階段       | 觸發                     | 揭露什麼                                                 |
| ---------- | ------------------------ | -------------------------------------------------------- |
| 1 首次成功 | 尚未 merge 過任何 task   | 連結專案 → 建立一個 task → 看 diff → merge。其餘入口收起 |
| 2 平行     | 已完成第一次 merge       | 提示可以同時開多個 task（這才是產品名字的意思）          |
| 3 進階     | 已同時跑過 2 個以上 task | 才顯示 Coordinator 與 Arena 的說明入口                   |

實作上**不引入 wizard 框架**：把既有空狀態串成序列，狀態存一個
persisted flag（`state.json` 已有 rolling backup 機制，沿用即可）。
新邏輯放 `src/lib` 當純函式 —— vitest 是 node 環境，component 層測不到。

### R2 — 離線模式總開關（Q3 = 要）

PRD §7.1 只列了三個連線點，實際盤點是**六個**：

| 模組                               | 對外行為                       |
| ---------------------------------- | ------------------------------ |
| `electron/ipc/updater.ts`          | GitHub Release 更新檢查        |
| `electron/ipc/pr-checks.ts`        | GitHub PR / check runs 輪詢    |
| `electron/ipc/ask-code.ts`         | Ask About Code（Claude CLI）   |
| `electron/ipc/ask-code-minimax.ts` | MiniMax API                    |
| `src/lib/marked-shiki.ts`          | Markdown 外部圖片（會洩漏 IP） |
| `electron/ipc/huly.ts`             | Huly 同步                      |

驗收：開關關閉時六者皆不發出請求，且 `PRIVACY.md` 與 PRD §7.1 同步更新為六項。
第三方 CLI 自身的網路活動不在此開關範圍內 —— 那是使用者授權的工具，文件要講清楚這條界線。
