## 3. 踩過的坑（不要重踩）

這些是實作過程中真的發生、並被守衛擋下來的。

### `git add -A` 會掃進不屬於你的檔案

`.agent/`、`.codex/`、`openspec/` 是 openspec CLI 生成的，**不該被追蹤**。
我用 `-A` 犯了兩次（`fa14d03`、`0160d91` 各修一次）。**這些 commit 請列明確路徑。**

### 沒有 linter 抓得到「imported but inert」

monaco 潛伏數個版本的原因不是 knip 設定錯 —— 是 **import 鏈是活的，所以 knip 是對的**。
沒有任何檔案或匯出「未被使用」，只是那個依賴從未被呼叫。
這類問題只能靠人工追問「這個 import 實際上被誰呼叫」，或靠 bundle size gate 兜底。

### `uploadMarkup` 不覆寫既有 blob

ref 由 (物件, 欄位, 版次) 決定、儲存 write-once。新 Huly issue 可以帶描述，
**既有 issue 的描述改不掉**。要更新就 **append comment**，那也正好符合欄位擁有權模型。

### 攔錯 console stream

Huly client 的警告走 `console.warn`，不是 `console.log`。第一版抑制是 no-op 卻沒人發現。
修法的關鍵是**把 sink 改成參數**，那才讓「選哪個 stream」變成可測。

### CSS import 順序

`App.tsx` 開頭那串 `.css` import **決定 cascade 順序**。在中間插一個 JS import 是無聲的樣式變更。
自動化腳本改 import 時要避開這個區塊。

### 效能改動先量再做

第三波量到 idle RSS 的變異是 346–523 MB —— **噪音蓋過 100 MB 以下的任何差異**。
單次取樣不可比，要同條件 median-of-N。`node scripts/measure-startup.mjs 9` 是現成的。

## 8. 交件流程 — Scott 怎麼把工作交給你

### 先知道這件事：你不需要等 push

兩個 worktree **共用同一份 `.git`**，所以分支與 commit 立刻互通。
在 `main` worktree 執行 `git branch` 會看到主 repo 的所有本地分支：

```
+ custom/theme-system     ← `+` 表示已被另一個 worktree checkout
* main
  personal
```

你現在就能讀任何分支的內容，不必等它被推上遠端：

```bash
git log --oneline main..feat/xyz          # 做了什麼
git diff main..feat/xyz                   # 改了什麼
git show feat/xyz:path/to/file            # 讀單一檔案
```

Push 仍然該做，但那是**備份**用途，不是你看得到的前提。

### Scott 開新功能的方式

他會在主 repo 開一個新的 worktree（或由 Orca / Parallel Code 自動建立）：

```bash
git worktree add ../pc-feat-xyz -b feat/xyz main                 # 獨立功能
git worktree add ../pc-feat-xyz -b feat/xyz custom/theme-system  # 依賴目前的改造
```

從哪裡分支出去會影響你的合併順序 —— 若是從 `custom/theme-system` 開的，
那條分支要先進 main，`feat/xyz` 才有意義。**收到交件時先確認基底。**

### 你會收到的交件長這樣

> `feat/xyz` 完成了，從 main 分出去的，N 個 commit。請 review 並評估合併。

收到後的標準動作：

```bash
git fetch                                 # 若對方有 push
git log --oneline main..feat/xyz
git diff main..feat/xyz
git merge feat/xyz                        # 在 main 上試合併
npm ci                                    # 依賴若有變動必須重裝
npm run check && npm run check:static && npm test
npm run check:bundle                      # 該分支若含 bundle gate
```

**關鍵在倒數兩步**：測試要跑在**合併之後**的結果上，不是分支本身、也不是原本的 main。
這是你這個角色存在的理由 —— 沒有一個真的 checkout 了 main 並合併過的目錄，這件事無法驗證。

驗證通過才 `git push origin main`。

### 三個容易忘的點

1. **每個新 worktree 都要自己 `npm ci`** —— `node_modules` 不共用。這是 worktree 唯一真正的成本
   （約 500 MB–1.2 GB／個），也是為什麼不該隨手開一堆。
2. **同一分支不能被兩個 worktree 同時 checkout。** 你想 `git checkout feat/xyz` 會被擋
   —— 但你**不需要** checkout 就能 merge，站在 main 上直接合併即可。
3. **合併完請 Scott 收掉 worktree**：`git worktree remove ../pc-feat-xyz`。
   若因 `node_modules` 刪不掉，加 `--force`；若已手動刪過目錄，補一次 `git worktree prune`。
