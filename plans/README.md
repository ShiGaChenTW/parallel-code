# plans/

每一波開發工作的追蹤文檔：決策理由、被推翻的判斷、以及當時查證過的東西。
這裡是**工作紀錄**，不是產品文件。要看產品現況請往 [`docs/`](../docs/README.md)。

## 規則

- 進行中的波次直接放 `plans/` 根目錄。
- 波次收掉後移進 `plans/archive/YYYY-MM/`，依**開工月份**分桶。
- 檔名沿用 `fork_parallel-code__YYYY-MM-DD-HHMM__<波次名>.md`。
- 歸檔只搬位置，**不修改內容**。這些是當下的紀錄，改了就不再是紀錄。

> `plans/` 沒有 `.gitignore` 允許清單，新檔案直接被追蹤。
> 這點和 `docs/` 相反 —— `docs/` 是逐檔允許清單，加檔案必須同步加規則。
>
> ⚠️ 不要改叫 `docs/plans/`。`electron/ipc/plans.ts:17` 的 `PLAN_DIRS`
> 會在每個 worktree 監看 `.claude/plans` 與 `docs/plans`，一個被追蹤的
> `docs/plans/` 會讓這 29 份文檔出現在 app 的 plan viewer 裡。

## 狀態的真相在哪

歸檔的文檔裡有 `**狀態：** 進行中` / `完成（未 push）` 這類行 —— 那是**寫下當時**的快照，
後來沒有回頭更新。`docs/ROADMAP.md` §1 才是完成狀態與 commit hash 的唯一真相來源。
這裡刻意不複製 hash：複製了就會漂移，而漂移的副本比沒有副本更糟。
